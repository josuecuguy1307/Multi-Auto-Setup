# MAS portable device (branch device/v0)

A portable device that carries its owner's AI (local model, agent harness, memory). Plugged into someone else's computer, and only
with that computer owner's permission, it connects the AI there without installing anything, inspects the machine read-only, and helps
set up MAS (Multi Auto Setup) on it, one approved write at a time with undo. A small key with a physical button is the only way to
approve a write: the limits live in the key's firmware and in the policy gate, not in the model. Source of truth: `MISSION.md`;
decisions: `DECISIONS.md`; where things stand: `ACCEPTANCE.md` (generated by the oracle) and `HANDOFF.md`.

## Honesty labels

Every result carries one label, in the code, in `ACCEPTANCE.md` and here:

- **SIMULATED**: a Python model on the development machine (for example the key's reference model, the host as a temporary folder).
- **EMULATED**: the real firmware or system running under an emulator or a virtual machine (QEMU, Renode, VMs).
- **DESIGN-ONLY**: a design that passed automatic checks but was never built (the PCB, the enclosure, the secure-boot plan).
- **REAL**: ran on real things (the repository itself, the oracle).

No board has been made. The fabrication files are stamped "NO FABRICAR sin revisión humana" and suffixed `_NO_FABRICAR`; the human
review list is `device/hardware/HUMAN_REVIEW_PCB.md`. Nothing here was tested on the actual key hardware.

**"No trace", defined (D-010).** The device never claims to leave no trace in the absolute. What it aims for, and what P2-ZEROTRACE
will measure, is: "Nothing installed: no service, driver, autostart, PATH change or file outside a declared temp dir removed on exit.
OS-generated residue is limited to an enumerated allowlist of classes" (USB device history, Prefetch and similar records the host's
operating system writes on its own).

## Where things are

| Path | What |
|---|---|
| `src/mas_device/approval.py` | Signed, single-use, expiring approval tokens (guardrail 3) |
| `src/mas_device/keymodel.py` | Python reference model of the key's firmware (SIMULATED) |
| `src/mas_device/gate.py` | The policy gate: the only code that writes to the host, with a fresh approval per write and a recorded undo |
| `src/mas_device/gated.py` | The gate as its own process, reached only through a fixed JSON-lines interface |
| `src/mas_device/log.py` | The append-only, hash-chained audit log |
| `device/firmware/` | The key's firmware in C (`device/firmware/README.md`), its secure-boot design (`device/firmware/SECURE_BOOT.md`) |
| `device/hardware/` | The key board as code: `device/hardware/design.py` is the source, `device/hardware/hwbuild.py` builds everything |
| `device/acceptance/criteria.yaml` | Every acceptance criterion: its tests, the files it covers, its label, its saboteurs |
| `device/tests/` | The tests behind every criterion |
| `device/evals/evaluator/` | Every independent evaluator report, verbatim |
| `scripts/device_accept.py` | The oracle: the only thing that writes `test-results.json` and the status table in `ACCEPTANCE.md` |

## Reproduce

One command runs every criterion and rewrites `test-results.json` and the table in `ACCEPTANCE.md`:

```
python scripts/device_accept.py run            # all criteria (about 40 minutes; the board rebuild is most of it)
python scripts/device_accept.py run --id P2-GATE
python scripts/device_accept.py status         # read-only
python scripts/device_accept.py verify         # read-only: fails if any recorded PASS is stale
python scripts/device_accept.py confirm        # the stop condition: clean tree, fresh worktree at HEAD, everything re-run
```

On Windows use `.venv/Scripts/python`; on POSIX `.venv/bin/python`. A criterion passes only if its tests pass, its minimum test count is
met and every saboteur (a deliberate break of the covered code) turns its tests red.

| Criterion | Label | What it shows | Needs |
|---|---|---|---|
| P1-HARNESS | REAL | the oracle treats skips and missing files as FAIL and detects stale results | Python |
| P1-DOCS | REAL | decisions, threat model, guardrail and PCB specs, advisor and reviewer advice are recorded | Python |
| P1-UNIT | SIMULATED | signed approvals, with an independent evaluator's PASS bound to the code's hash | Python |
| P2-GATE | SIMULATED | writes only with a fresh approval for the exact action; undo recorded first | Python |
| P2-LOG | SIMULATED | the audit log detects any edit, cut or reorder against a known head | Python |
| P2-GUARDRAILS | SIMULATED | a scripted malicious model gets zero violations of the ten guardrails | Python |
| P2-PORTABLE | EMULATED | one-command launch from a read-only medium in a clean VM | not built yet; needs VMs or containers |
| P2-ZEROTRACE | EMULATED | the D-010 three-arm disk diff | not built yet; needs VMs |
| P2-FLEET | EMULATED | pairing, per-write approval and undo between isolated VMs | not built yet; needs VMs |
| P2-MODEL | EMULATED | the local model answers from the read-only medium | not built yet; needs a local model |
| P2-MEMORY | SIMULATED | portable memory in an open format, encrypted at rest | not built yet |
| P2-PAIRING | SIMULATED | the gate accepts only the key paired with the medium (`pairing.json`); the owner sees the session terms at launch; MAS chat approvals absent from the device build | Python |
| P3-INSPECT | SIMULATED | inventory precision and recall against fixtures with known truth | not built yet |
| P3-READONLY | EMULATED | inspection makes zero writes and no network access | not built yet; needs VMs |
| P3-REPORT | SIMULATED | the inspection report is schema-checked | not built yet |
| P3-NOCREDS | SIMULATED | planted secrets never reach the report or the model | not built yet |
| P4-FW-HOST | SIMULATED | the firmware rejects replayed, altered and expired approvals; signs only after a press | zig |
| P4-FW-EMU | EMULATED | the same firmware in QEMU gives identical transcripts | zig, QEMU |
| P4-FW-RENODE | EMULATED | the same firmware in Renode gives identical transcripts | zig, Renode |
| P4-SECBOOT | DESIGN-ONLY | the secure-boot and lock design matches the firmware's assumptions | Python |
| P5-PCB | DESIGN-ONLY | ERC, DRC and fabrication checks green, board facts read through pcbnew | KiCad |
| P5-ENCLOSURE | DESIGN-ONLY | a parametric enclosure fits the board by automatic check | Python |
| P6-EVALS | REAL | evals reproducible with one command | not built yet |
| P6-REPO | REAL | this file, `THIRD_PARTY.md`, reproduction instructions | Python |
| P6-PAPER | REAL | the paper regenerates from raw results | not built yet |
| P0-SECRETS | REAL | no credentials anywhere in the tree or its history | git |

The board alone: `python device/hardware/hwbuild.py --out runs/hw/out` (5 to 10 minutes). The firmware alone:
`python device/firmware/build.py`.
