# Router environments (data, not code)

`references/environments.json` is the curated catalog: written by the project, never by a model. Each entry has a subtype (`provider`, `own_harness`, `local_model`; `embedded` is declared but has no entry yet), the task types it serves, operating systems, what it needs, its license, its upstream and pin, its `automated_use` state, its accesses (what enables it on a machine, with a cost class and, for a plan, a `plan_group` whose members share a quota counter), and an `adapter` (executable name per operating-system family, the arguments per task type, the environment variables it may receive by NAME, how the answer is read, and the confinement of each mode).

Every field that decides routing is labelled in `labels`: `verified by code` (a program read it) or `declared by the project` (quoted from a document, with its source). A field with no label is not used. `confinement` is the honest state of what keeps the tool inside its workspace: `none_needed` (no tools), `tool_declared` (the vendor documents a switch; not verified by us), `unverified` (nothing documented or not verified; needs our sandbox backend) or `sandbox_required` (the tool says it has no confinement of its own). Only our sandbox backend, or `none_needed`, is trusted without a test of our own.

`references/policy.json` holds the rule's visible configuration (tie margin, cost order, escalation cap) and the defaults of the owner policy until the owner's draft (T3b) provides them: which subtypes are open, which providers are approved for internal work, which environments the owner has cleared for automated use.

`cloud` says whether a run sends data out of the owner's network. It is a property of the environment and, when an access declares its own `cloud`, of that ACCESS: one environment can run on a loopback model through one access and on an API through another. An access that does not declare it inherits the environment's. Sensitivity filters, the dispatch guard and the node all read it per access (`envrun.is_cloud`), and the signed scope names the access. Declare `cloud: true` on any access whose endpoint is not a loopback literal.

Task types are data too. A type exists when an environment lists it in `task_types` with a mode for it under `adapter.modes`, and a suite `data/admission/<type>-v1/suite.yaml` holds its ten code-graded tasks (a type without a suite cannot be measured, so nothing about it is ever "measured here"). No list of types lives in code. To add a type: one suite file, plus the type and its mode in each environment that serves it. `tests/test_task_types_as_data.py` checks that the two sides agree.

An access may carry its own `adapter`, laid over the environment's (`envrun.adapter_of`): OpenCode runs on the node's loopback llama.cpp server through `opencode:local` and on the Meta Model API through `opencode:meta-api`, which names its address in the config and takes the key by NAME from the environment (`env_pass`). An adapter that names its own address (`base_url`, https only) is an API: its access must declare `cloud: true`, it takes no endpoint from the coordinator, its credential is named in `auth.env_name` (the node reads the value from its credential store or environment, only for that run) and `body_fields` lists the only request fields it sends. `envrun.check_catalog` refuses a catalog that breaks this, and the node loads nothing else. `needs_program: false` marks an environment with nothing to install (an API). `model` on an environment or an access is the model id the data names; without it the machine's own local model is the one.

A change to either file is reviewed like code. A new environment arrives only through a manifest here with its labels; the router and the node read it, and neither carries a tool name, a flag or a path of its own (checks P1, H1).


## Domain tags and skill packs
- `domains` of an entry are written only from what its own source states (the description and topics of its repository, or the description of its documentation page), by the rules in `references/domain_sources.json`, read by code from stored captures (`domains_source`). An entry whose sources state no work domain keeps `[]` and says `states_no_domain`; never add a tag by hand.
- A `skill_pack` entry is a set of files an environment reads (instructions), not an environment: no adapter, no access, never routed. It is pinned to a 40-hex commit, each file by its address at that commit and its SHA-256, under a permissive license, and names the environments it is for (`pack_for`). It is installed through a plan like a tool (`mas_install_tool`): one checked download per file into the pack's own folder, and only on a computer that has one of the environments it is for.
